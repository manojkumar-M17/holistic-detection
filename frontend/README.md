# Holistic Detection frontend

Responsive React, TypeScript, and Vite console for the existing Flask examination-monitoring service. Dashboard values, incident records, charts, and review state are populated from the backend; the frontend does not seed demonstration student or alert records.

## Local development

From this directory:

```sh
npm ci
npm run dev
```

The production backend URL is configured in `.env.production`. Set `VITE_API_BASE_URL` in a local `.env.local` file if you need to use a different backend. Vite variables are public client configuration, not a place for credentials or secrets.

```sh
npm run lint
npm run build
npm run preview
```

## Backend API integration

The frontend uses the routes found in `dashboard/app.py`:

| Route | Frontend use |
| --- | --- |
| `GET /api/stats` | Live summary, risk scores, severity/category counts, and audio metrics; requires the prototype API key |
| `GET /api/alerts` | Incident list, filters, activity history, student incident records; requires the prototype API key |
| `GET /api/stream-events` | Server-Sent Events for telemetry updates and newly recorded incidents; requires the prototype API key |
| `POST /api/incidents/{id}/status` | Confirm or dismiss a reviewable incident |
| `GET /api/incidents/export` | Download the incident CSV; requires the prototype API key |
| `GET /api/report/pdf` | Open the printable HTML report generated by the backend; requires the prototype API key |
| `GET /api/config`, `POST /api/config` | Read and update detection thresholds and feature flags; both require the prototype API key |
| `POST /api/control/pause`, `POST /api/control/resume` | Pause or resume backend monitoring; requires `X-API-Key` |
| `GET /screenshots/{filename}` | Open incident evidence when a screenshot path is present; requires the prototype API key |
| `GET /video_feed` | Legacy MJPEG stream; requires the prototype API key |

The API source does not expose authentication, a student directory, exam/session details, per-module confidence scores, an audio upload path, or a browser-camera ingestion endpoint. The `/api/report/pdf` route returns `text/html`, not a PDF file. Those UI areas are explicitly identified rather than populated with invented values. The browser camera is an opt-in local preview and is not transmitted to the backend.

The latest live checks were made against the then-deployed Render revision and returned HTTP 200 with allowlisted CORS for `/api/stats`, `/api/alerts`, and `/api/config`; the stats and alert payloads contained zero records. That deployed revision returned 404 for `/api/health` and did not allow `X-API-Key` in preflight. The protections described here are worktree changes and are not active in production until the backend revision is deployed and verified. Do not treat the currently deployed service as protected based on this documentation.

Protected reads and writes require an `API_WRITE_TOKEN` configured on Render. An operator can enter that shared key on the Settings page; it is held in JavaScript memory for the current page session and sent as `X-API-Key` on protected requests, including report/evidence fetches and the SSE stream. It is not embedded in the frontend build or saved in browser storage, but browser users who enter it can inspect and copy it. This is a temporary prototype restriction, not user authentication, identity, or role-based access control. Do not use it as an institutional security boundary.

## Vercel deployment

1. Import the repository in Vercel and set **Root Directory** to `frontend`.
2. Select the **Vite** framework preset.
3. Use `npm ci` for Install Command and `npm run build` for Build Command. The output directory is `dist`.
4. In **Project Settings → Environment Variables**, set `VITE_API_BASE_URL` to `https://holistic-detection.onrender.com` for Production (and Preview if required). Rebuild/redeploy after changing it; Vite embeds this value at build time.
5. Ensure the Flask deployment is healthy and its CORS allowlist includes the final Vercel domain. Test the dashboard, SSE stream, incident review, export, settings, and report route against that deployment.

`vercel.json` rewrites client-side routes to the Vite entry point so deep links such as `/monitoring` and `/activities` load correctly.
